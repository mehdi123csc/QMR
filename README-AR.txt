متجر Qmr — النسخة الفاخرة | دليل التثبيت والنشر
================================

المحتويات
- index.html / style.css / script.js: واجهة المتجر وسلة الطلبات. تأكد أن الاسم هو index.html بالضبط.
- admin.html / admin.css / admin.js: لوحة الإدارة.
- config.js: بيانات الربط العامة مع Supabase (فارغة افتراضيًا).
- supabase-setup.sql: الجداول وسياسات RLS والتخزين.
- assets/qmr-logo.jpg: اللوغو الذي أرسلته، مع بديل تلقائي باسم Qmr إذا تعذر تحميل الصورة.

مهم قبل استقبال طلبات حقيقية
-----------------------------
1. ارفع ملفات هذا المجلد إلى مستودع GitHub.
2. افتح مشروع Supabase أو أنشئ مشروعًا جديدًا.
3. للمشروع الجديد: من SQL Editor شغّل كامل ملف supabase-setup.sql. للمشروع الحالي الذي لا تظهر فيه المنتجات: شغّل ملف supabase-fix-products.sql فقط.
4. من Project Settings > API انسخ Project URL و anon/public key (أو publishable key) فقط، وضعهما في config.js (الملف المرفق مُعدّ بالفعل لمشروع QMR الحالي):
   SUPABASE_URL: "https://YOUR-PROJECT.supabase.co"
   SUPABASE_ANON_KEY: "YOUR_PUBLIC_ANON_KEY"
   لا تضع service_role أو secret key في أي ملف يصل للمتصفح.
5. من Authentication > Users أنشئ حساب الإدارة ببريدك وكلمة مرور قوية.
6. انسخ UUID الخاص بالمستخدم من Authentication > Users. في SQL Editor نفّذ:
   insert into public.profiles (id, role)
   values ('ضع-UUID-هنا', 'admin')
   on conflict (id) do update set role = 'admin';
7. افتح https://YOUR-SITE/admin.html وسجّل الدخول.
8. أضف منتجًا تجريبيًا، جرّب الطلب، ثم تحقق من ظهوره في جدول orders.
9. اختبر سياسات RLS بحساب زائر وحساب إدارة قبل مشاركة المتجر.

الصور
-----
يمكن لصق رابط HTTPS لصورة أو اختيار صورة من الهاتف من لوحة الإدارة.
رفع الصور من الهاتف يحتاج إلى ضبط Storage والسياسات من SQL script.
صور المنتجات التجريبية تستخدم روابط صور خارجية؛ استبدلها بصور منتجاتك المصرح لك باستخدامها.

النشر على GitHub Pages
----------------------
- ارفع الملفات في جذر المستودع (بحيث يكون index.html في الجذر).
- في GitHub > Settings > Pages اختر النشر من الفرع الرئيسي (main) والمجلد /(root)، أو استخدم إعداد النشر المتاح في مستودعك.
- انتظر اكتمال النشر، ثم اختبر الموقع ورابط admin.html.
- GitHub Pages يدعم HTTPS. لا تضع بيانات سرية في المستودع؛ الموقع وملفات JavaScript عامة.

النشر على Cloudflare Pages
--------------------------
الأفضل ربط نفس مستودع GitHub بمشروع Cloudflare Pages حتى يُنشر كل تحديث تلقائيًا:
- Workers & Pages > Create application > Pages > Connect to Git.
- اختر المستودع والفرع main.
- لموقع HTML عادي: Build command = exit 0، وBuild output directory = / (جذر الملفات) بحسب واجهة إعداد المشروع.
- بعد النشر اختبر رابط pages.dev وadmin.html.

الأمان وحدود النسخة
-------------------
- هذه واجهة ثابتة، وليست خادمًا خاصًا. الحماية الحقيقية تعتمد على Supabase Auth وRLS؛ إخفاء صفحة الإدارة وحده ليس حماية.
- لا تُدخل أي مفاتيح سرية في config.js. مفتاح anon/public مصمم للاستخدام من المتصفح مع سياسات RLS صحيحة.
- سياسة الزوار تسمح بإرسال طلب فقط ولا تسمح لهم بقراءة الطلبات أو تعديلها. الإدارة تحتاج مستخدمًا محددًا بدور admin.
- مجموع السعر المرسل من المتصفح قابل للتلاعب تقنيًا؛ قبل تشغيل المتجر تجاريًا يفضّل إنشاء Edge Function تتحقق من أسعار المنتجات والمخزون وتحسب الإجمالي على الخادم، مع حماية من السبام.
- بيانات الطلبات تتضمن الهاتف والعنوان؛ لا تشاركها علنًا، وامنح صلاحية الإدارة فقط لمن تثق بهم.
- لا يتم إرسال طلب فعلي عندما يكون Supabase غير مربوط؛ الموقع يعرض تنبيهًا بدل الادعاء بأن الطلب نجح.


إصلاح مهم للمشروع الحالي
------------------------
- ملف script.js يقرأ الآن المفتاح من QMR_CONFIG.SUPABASE_ANON_KEY كما هو موجود في config.js.
- ملف supabase-fix-products.sql يعالج سياسة قراءة المنتجات للزوار دون منح الزوار صلاحية قراءة الطلبات.
- ارفع index.html (وليس index (1).html) إلى جذر مستودع GitHub.
- لا ترفع أي service_role أو secret key إلى GitHub.
