متجر Qmr — النسخة المنظّمة والمحسّنة
========================================

ما الذي تم تحسينه؟
- توحيد بنية المشروع بحيث تكون index.html في جذر المجلد، بدل مجلد متداخل داخل ZIP.
- تقوية التعامل مع سلة التسوق عند تعطل localStorage، وتنقية بيانات السلة المحفوظة وتحديد الكمية من 1 إلى 99.
- إظهار تنبيه واضح عند تعذّر تحميل كتالوج Supabase بدل إخفاء المشكلة.
- تحسين بيانات المشاركة الأساسية لمحركات البحث والشبكات الاجتماعية.
- التحقق من دعم HTTPS/crypto قبل رفع الصور، ومسح اختيار الصورة بعد الحفظ أو الإلغاء.
- إضافة قيود أولية على عدد عناصر الطلب وملاحظاته في SQL.

تشغيل الموقع
------------
1. فك ضغط الملف، وارفع محتويات هذا المجلد إلى جذر استضافة الموقع.
2. تم ضبط config.js مسبقًا على مشروع Supabase الجديد. رابط SUPABASE_URL يجب أن يكون رابط المشروع الأساسي دون /rest/v1/.
3. من Supabase SQL Editor شغّل supabase-setup.sql.
4. في Supabase Authentication أنشئ مستخدم الإدارة.
5. انسخ UUID للمستخدم من Authentication > Users ثم نفّذ، بعد استبدال القيمة:
   insert into public.profiles (id, role)
   values ('UUID-الحقيقي-للمستخدم', 'admin')
   on conflict (id) do update set role = 'admin';
6. افتح /admin.html وسجّل الدخول وأضف منتجات حقيقية.
7. جرّب إضافة منتج، رفع صورة، إرسال طلب تجريبي، وتغيير حالة الطلب قبل إطلاق الموقع.

إعداد config.js
----------------
window.QMR_CONFIG = {
  SUPABASE_URL: "https://ssuadfuscyjnmceonccv.supabase.co",
  SUPABASE_ANON_KEY: "ضع_المفتاح_العام_في_ملف_config.js"
};

لا تضع service_role أو أي secret key في JavaScript أو GitHub أو المتصفح.
مفتاح anon/publishable عام بطبيعته؛ الأمان يعتمد على سياسات RLS الصحيحة.

ملاحظات مهمة قبل اعتبار الموقع متجرًا عالميًا
---------------------------------------------
هذه النسخة ما زالت متجرًا ثابتًا (HTML/CSS/JavaScript) مرتبطًا بـ Supabase؛ لا يمكن ضمان أنها جاهزة عالميًا دون تشغيلها على مشروع Supabase فعلي واختبار إعداداته وبياناته.

- إجمالي الطلب والأسعار المرسلة من المتصفح يمكن التلاعب بها. قبل استقبال طلبات تجارية حقيقية، انقل إنشاء الطلب إلى Supabase Edge Function تتحقق من المنتجات والأسعار والمخزون وتحسب الإجمالي على الخادم، وتطبق تحديد المعدل ومكافحة السبام.
- لا توجد بوابة دفع إلكتروني أو تكامل شركات شحن عالمي في هذه النسخة؛ الدفع الحالي عند الاستلام ومحتوى الواجهة مهيأ أساسًا للجزائر.
- يجب مراجعة سياسات RLS في مشروعك الفعلي، واختبارها بحساب زائر وحساب إدارة. لا تعتبر مجرد إخفاء صفحة admin حماية.
- فعّل تأكيد البريد وسياسة كلمات مرور قوية، واحمِ بيانات الهاتف والعنوان، ولا تشاركها علنًا.
- ارفع الموقع عبر HTTPS على Cloudflare Pages أو استضافة مشابهة. اضبط اسم النطاق وDNS بعد امتلاك النطاق.
- راجع حقوق صور المنتجات، وأضف سياسة الخصوصية والاسترجاع والتوصيل وشروط البيع ومعلومات التواصل قبل النشر التجاري.
- لا يمكن إعداد Supabase الفعلي أو التحقق من مفاتيحه دون رابط المشروع وإعداداتك، ولم يتم تشغيل هذا الملف على قاعدة بيانات حقيقية هنا.

النشر على GitHub Pages
----------------------
ارفع الملفات في جذر المستودع ثم من Settings > Pages اختر النشر من الفرع main ومجلد /(root). انتظر النشر، ثم اختبر الموقع و/admin.html.

النشر على Cloudflare Pages
--------------------------
اربط مستودع GitHub بمشروع Pages. لموقع HTML عادي اجعل Build command فارغًا أو `exit 0` حسب الواجهة، ومجلد الإخراج هو جذر المشروع. اختبر رابط pages.dev بعد النشر.

الملفات الرئيسية
----------------
- index.html / style.css / script.js: واجهة المتجر والسلة والطلبات.
- admin.html / admin.css / admin.js: لوحة الإدارة.
- config.js: إعداد الربط العام مع Supabase.
- supabase-setup.sql: الجداول والسياسات والتخزين.
- assets/qmr-logo.jpg: شعار المتجر.

معلومات المشروع الحالي
----------------------
رابط المشروع: https://ssuadfuscyjnmceonccv.supabase.co
ملف config.js مضبوط على المفتاح العام الذي زودنا به المستخدم.
لم يتم اختبار الاتصال بالشبكة أو تشغيل SQL على قاعدة البيانات الحقيقية من داخل هذه العملية.


تحديث الإصلاحات: تم دعم فتح صورة المنتج عند الضغط عليها، وأصبح حقل رابط الصورة اختياريًا عند اختيار صورة من الهاتف. لرفع الصور يلزم أن يكون Storage bucket باسم product-images موجودًا وسياسات الرفع المذكورة في supabase-setup.sql مطبقة. لم تُعدّل قاعدة البيانات تلقائيًا من هذه الحزمة. بعد رفع الملفات إلى GitHub اختبري طلبًا تجريبيًا، وإذا ظهر خطأ في الإرسال راجعي Console/Supabase Logs مع رمز الخطأ الظاهر.

ترقية Qmr — المخزون والكوبونات والبلديات والصور المتعددة
------------------------------------------------------
بعد تشغيل supabase-setup.sql، شغّل ملف supabase-global-upgrade.sql في Supabase SQL Editor. التحديث يضيف:
- مخزون المنتجات وعدّ الكمية تلقائيًا عند إنشاء الطلب عبر RPC.
- كوبونات بنسبة مئوية أو مبلغ ثابت، حد أدنى للطلب، وتاريخ انتهاء.
- حتى 4 صور لكل منتج.
- حفظ البلدية مع الولاية.
- إنشاء الطلب على الخادم عبر qmr_place_order للتحقق من السعر الفعلي والمخزون والكوبون، بدل الثقة بسعر المتصفح.
- منع الإدخال المباشر القديم للطلبات من المتصفح؛ يجب أن يستخدم الموقع النسخة الجديدة من script.js.
- إدارة الكوبونات وحذف الطلب من لوحة الإدارة. حذف الطلب نهائي ويطلب تأكيدًا.

قائمة البلديات:
تُحمّل قائمة الولايات والبلديات الـ69/1541 من ملف بيانات مفتوح عند فتح صفحة المتجر. يتطلب ذلك اتصال إنترنت؛ إذا تعذر تحميل البيانات يتحول حقل البلدية إلى إدخال يدوي. مصدر البيانات: https://github.com/wadiemendja/algeria-communes-wilayas — تحقّق من آخر تحديث إداري قبل الاستخدام الرسمي.

مهم قبل إطلاق تجاري:
- المنتجات الجديدة تبدأ بمخزون 0؛ أدخل الكمية الحقيقية من لوحة الإدارة قبل إظهارها للبيع.
- التحديث لا يحذف أي طلب سابق، بما في ذلك الطلبات التجريبية الموجودة.
- الدفع الإلكتروني، أسعار العملات الحية، شركات الشحن الدولية، رسائل SMS/البريد، وواجهة فرنسية كاملة لم تُفعّل تلقائيًا. لا تعتبر المتجر جاهزًا عالميًا حتى ربط مزود دفع وشحن مناسبين لبلدك واختبار كل مسارات الطلب فعليًا.
- بعد تشغيل SQL ارفع جميع ملفات المشروع إلى جذر المستودع، بما فيها qmr-logo.jpg وsupabase-global-upgrade.sql. لا ترفع مفاتيح سرية.
